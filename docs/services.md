# Service documentation

Region: **ap-southeast-1 (Singapore)** since Assignment 3 (Assignment 2 used ap-south-1), two Availability Zones. WAF and the CloudFront certificate live in `us-east-1`, as CloudFront requires. All configuration is in `infra/` (Terraform). Rows marked **[A3]** changed in Assignment 3 – see `architecture/README.md` change log and `docs/cost-report.md`.

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon Route 53** | DNS for `exams.<university-domain>` | Alias records to CloudFront are free and resolve at the apex; a registrar's DNS can't alias to CloudFront and has no health checks | Public hosted zone; A/AAAA **alias** → CloudFront; ACM DNS-validation records. Optional (`domain_name` variable) – the CloudFront default domain is used if unset | CloudFront, ACM |
| **AWS Certificate Manager** | TLS certificate for the custom domain | Free, auto-renewing; vs buying/uploading certificates that expire and must be rotated by hand | Public cert in us-east-1, DNS validation | CloudFront, Route 53 |
| **Amazon CloudFront** | CDN and single entry point for SPA and API | Edge caching absorbs the exam-start page-load spike and gives one origin (no CORS) – vs serving straight from S3 website hosting (HTTP only, public bucket) or from an ALB (all traffic hits the region) | Two origins: S3 frontend via **Origin Access Control**, API Gateway for `/api/*` (custom no-cache policy that forwards the `Authorization` JWT, AllViewerExceptHostHeader). HTTPS-only (redirect), TLS 1.2+, HTTP/2+3, managed security-headers policy, PriceClass_200 (includes India) | Route 53, WAF, ACM, S3 frontend, API Gateway |
| **AWS WAF** | Layer-7 filtering in front of everything | Managed, attached at the edge; vs Shield Advanced alone (DDoS only, $3k/month) or app-level checks (attacks already reach the region) | Web ACL (CLOUDFRONT scope): AWSManagedRulesCommonRuleSet, KnownBadInputs, AmazonIpReputationList, **rate-based rule 10,000 req / 5 min per IP** (sized so a 300-seat exam hall behind one campus NAT IP – about 3,000 autosaves per 5 min – is never blocked) | CloudFront, CloudWatch |
| **Amazon S3 (frontend)** | Hosts the static single-page app | Static files need no servers; vs Amplify Hosting (less control over WAF/OAC/IaC) or EC2/nginx (patching, scaling) | Private bucket, Block Public Access on, bucket policy allows only this CloudFront distribution (OAC, SigV4), SSE-S3, versioning | CloudFront, GitHub Actions |
| **Amazon S3 (uploads)** | Stores assignment files (PDF/ZIP ≤ 50 MB) for 5 years | Cheaper and more durable (11 nines, 3+ AZs) than EBS/EFS; **presigned POST** keeps 50 MB uploads off API Gateway (10 MB limit) and Lambda (6 MB limit) | Block Public Access, **SSE-KMS** with CMK + bucket key, versioning, TLS-only bucket policy (`aws:SecureTransport`), CORS for the site origin (POST), **lifecycle**: Standard → Standard-IA at 30 d → **Glacier Deep Archive at 180 d [A3]** → expire at 1,825 d (5 yr); noncurrent versions expire after 30 d; abort incomplete multipart after 7 d. `ObjectCreated` → SQS | CloudFront (site origin for CORS), API Lambda (presign), upload-processor Lambda, SQS, KMS, IAM |
| **Amazon Cognito User Pool** | Sign-in and roles (students, tutors, admins) | Managed OAuth2/OIDC with MFA and hosted UI, natively validated by API Gateway; vs self-built auth (password storage risk) or IAM Identity Center (workforce SSO, not for 8,000 students). Can federate to the university's Entra ID/SAML later | Groups `students`, `tutors`, `admins`; email as username, password policy 12+ chars, optional TOTP MFA (required for staff by policy), admin-create-user only (no self sign-up), **Hosted UI** with authorization-code + PKCE, access token 60 min, refresh 12 h | Browser, API Gateway authorizer, API Lambda (admin user management) |
| **Amazon API Gateway (HTTP API)** | Public API front door | ~70 % cheaper and lower latency than REST API, has a native JWT authorizer; vs ALB (no built-in JWT/throttling, needs VPC public subnets and always-on cost) | Routes `ANY /api/{proxy+}` → API Lambda, **JWT authorizer** (issuer = user pool, audience = app client), default route throttling **burst 2,000 / rate 1,000 rps**, access logs to CloudWatch | CloudFront, Cognito, API Lambda, CloudWatch |
| **AWS Lambda – `api`** | Business logic: exams, attempts, autosave, results, presigned URLs, admin | Scales to the 3,000-student peak in seconds with no idle cost; vs ECS Fargate/EC2 (must pre-scale tasks, pay 24/7 for an exam-season workload) | Node.js 22, arm64, 512 MB, 10 s timeout, **in VPC private app subnets of both AZs**, security group egress to RDS Proxy 5432 + HTTPS, alias `live` with 100 provisioned concurrency in `exam_mode` [A3], IAM auth to RDS Proxy | API Gateway, RDS Proxy, S3 (presign), SQS, Cognito, Secrets Manager, CloudWatch |
| **AWS Lambda – `marker`** | Auto-marks MCQs after submission | Event-driven and isolated from the API, so marking bursts at the deadline don't slow live exams; vs marking inline in the submit call (slower, fails the request on error) | SQS trigger batch 10, `ReportBatchItemFailures`, event-source max concurrency 20 [A3], private subnets | SQS marking-queue, RDS Proxy |
| **AWS Lambda – `upload-processor`** | Validates uploaded file, records submission, emails tutor | Same as above; vs S3 → Lambda direct (no buffering/DLQ) | SQS trigger batch 5, checks size ≤ 50 MB and `%PDF`/`PK` magic bytes, quarantines bad files | SQS uploads-queue, S3, RDS Proxy, SES |
| **AWS Lambda – `notifier`** | Emails students when results are released | Queue-driven fan-out respects SES sending rate; vs sending 8,000 emails in one API call (times out) | SQS trigger batch 10, max concurrency 5; fans out to the email queue [A3] | SQS notify-queue, SES, RDS Proxy |
| **AWS Lambda – `migrate`** | Applies the SQL schema | Runs inside the VPC so the DB never needs a public endpoint or a bastion host | Invoked by the pipeline after `terraform apply` | RDS Proxy, GitHub Actions |
| **AWS Lambda – `mailer`** [A3] | Sends every email via SES | Runs **outside the VPC**, so VPC functions need no NAT to reach SES; one queue lets us cap the SES send rate | Node.js 22 arm64, 256 MB, SQS `email` trigger, event-source max concurrency 5 | SQS email-queue, SES |
| **AWS Lambda – `admin`** [A3] | Creates users and assigns Cognito groups | Outside the VPC (Cognito only), so no NAT needed | `ANY /api/admin/{proxy+}` route, admins group only | API Gateway, Cognito |
| **Amazon SQS** (4 queues + 4 DLQs) [A3: + email queue] | Buffers async work: marking, upload processing, notifications | Fully managed, at-least-once, DLQ, no capacity planning; vs SNS alone (no buffering/retry back-pressure) or Kinesis (ordered streams not needed, pricier) | SSE-SQS, visibility timeout 6× function timeout, `maxReceiveCount` 5 → DLQ (14-day retention), CloudWatch alarm on DLQ depth > 0 | API Lambda, S3, worker Lambdas, CloudWatch |
| **Amazon SES** | Sends tutor and result emails | Cheapest bulk transactional email ($0.10/1,000), DKIM/SPF; vs SNS email (no HTML, recipients must confirm subscription) or a third-party SaaS | Verified domain identity (or verified addresses in sandbox), DKIM, configuration set for bounce tracking; request production access before go-live | upload-processor and notifier Lambdas |
| **Amazon VPC** | Private network isolation | Keeps DB and compute off the internet | 10.0.0.0/16; per AZ: **public** /24 (NAT GW), **private app** /24 (Lambda ENIs, RDS Proxy), **private data** /24 (RDS); IGW; route tables per tier; **S3 gateway endpoint** (free, keeps S3 traffic private); VPC Flow Logs → CloudWatch | All in-VPC resources |
| **VPC endpoints** [A3] | Private access to AWS services with **no NAT gateway** | 2 NAT gateways cost $1,037/yr vs $456/yr for endpoints, and NAT was a per-AZ failure point; no internet egress also lowers exfiltration risk | S3 **gateway** endpoint (free) on app route tables; **interface** endpoints for SQS and Secrets Manager with an ENI in each app subnet, private DNS on, SG allows 443 from the VPC only | Lambdas, RDS Proxy, S3, SQS, Secrets Manager |
| **Security groups** | Stateful firewall per tier | Least-privilege by reference, vs NACL-only (stateless, IP-based) | `lambda-sg` → `proxy-sg` 5432; `proxy-sg` → `db-sg` 5432; DB has **no** public access and no other inbound | Lambda, RDS Proxy, RDS |
| **Amazon RDS for PostgreSQL (Multi-AZ)** | System of record: users, exams, questions, attempts, answers, submissions, results | Relational data with joins and transactions (attempt + answers + marks) and synchronous standby in a 2nd AZ; vs DynamoDB (harder ad-hoc reporting for tutors) or Aurora (higher minimum cost for this size; good upgrade path) | PostgreSQL 16, `db.t4g.medium` on a **1-yr RI** in normal months, **`db.t4g.large` in `exam_mode` [A3]**, **Multi-AZ**, gp3 50 GB auto-scaling to 200 GB, `publicly_accessible = false`, private data subnets, **storage encrypted with KMS CMK**, `rds.force_ssl = 1`, **backup retention 35 days (PITR, RPO ≤ 5 min)**, Performance Insights, deletion protection (prod), master password managed in Secrets Manager | RDS Proxy, KMS, Secrets Manager, AWS Backup, CloudWatch |
| **Amazon RDS Proxy** | Connection pooling and faster failover | Hundreds of concurrent Lambdas would exhaust PostgreSQL connections; Proxy pools them and cuts failover time up to ~66 %; vs pgBouncer on EC2 (self-managed, single AZ) | Subnets in both AZs, `require_tls = true`, **client IAM auth required [A3]** (Lambdas sign a token locally), proxy reads the DB secret, idle timeout 30 min, max connections 75 % | Lambdas, RDS, Secrets Manager |
| **AWS Secrets Manager** | Holds DB credentials | Built-in rotation and RDS integration; vs SSM Parameter Store SecureString (no native rotation) or env vars (plaintext in console) | RDS `manage_master_user_password = true` (rotated every 7 days), encrypted with the CMK; only RDS Proxy and `migrate` Lambda may read it | RDS, RDS Proxy, Lambda, KMS |
| **AWS KMS** | Customer-managed encryption key for data at rest | CMK gives key policy control, rotation and CloudTrail audit of every decrypt; vs AWS-managed keys (no policy control) | Symmetric CMK, **annual automatic rotation**, alias `alias/exam-platform`, used by S3 uploads, RDS, Secrets Manager, CloudWatch Logs, SNS | S3, RDS, Secrets Manager, SQS, CloudWatch |
| **AWS IAM** | Least-privilege roles for every function and the pipeline | Native; per-function roles limit blast radius | One role per Lambda (e.g. `api` may only `s3:PutObject` presign on `submissions/*`, `sqs:SendMessage` to two queues); GitHub OIDC deploy role restricted to `repo:<owner>/<repo>:ref:refs/heads/main` | All services |
| **Amazon CloudWatch** | Logs, metrics, dashboard, alarms | Native to every service used; vs self-hosted Prometheus/Grafana (run and scale yourself) | Log groups 30-day retention, JSON logs at WARN, access and flow logs in the Infrequent Access class [A3] (KMS); dashboard (API 4xx/5xx/latency, Lambda errors/throttles/concurrency, RDS CPU/connections, SQS age/DLQ); alarms: API 5xx > 1 %, Lambda throttles > 0, RDS CPU > 80 %, DLQ > 0, SQS oldest message > 5 min → SNS | All services, SNS |
| **Amazon SNS** (ops topic) | Delivers alarms to the on-call team | Fan-out to email/SMS/Chatbot; vs polling the console | Topic encrypted with KMS, email subscription `alarm_email` | CloudWatch |
| ~~AWS X-Ray~~ [A3: removed] | – | Cost $152/yr for traces nobody read outside incidents; CloudWatch p95 latency, Lambda duration and JSON error logs give the same signals for this app | – | – |
| **AWS CloudTrail** | Audit log of every API call (who released which results) | Required for exam-integrity investigations; vs relying on app logs | Multi-region trail to an encrypted, versioned S3 bucket (5-year lifecycle), log-file validation on | S3, KMS |
| **AWS Backup** | Long-term DB records (5 years) | Automated backups max out at 35 days; Backup adds monthly copies kept 5 years; vs manual snapshots (forgotten, not policy-enforced) | Plan: daily (kept 35 d) and monthly (kept 1,825 d = 5 yr); vault encrypted with the CMK | RDS, KMS |
| **GitHub Actions** | CI/CD: test, `terraform apply`, deploy SPA, migrate | Code already lives on GitHub, free minutes, OIDC means **no stored AWS keys**; vs CodePipeline + CodeBuild (extra service to wire up, still needs a GitHub connection) | `.github/workflows/deploy.yml`: on PR → lint/test/`terraform plan`; on push to `main` → `terraform apply` → `npm run migrate` → `aws s3 sync` → CloudFront invalidation | IAM (OIDC), S3 state bucket, all deployed resources |
| **Terraform + S3 state** | Infrastructure as code | Whole stack reproducible from Git; plan shows diffs before apply; vs console-built (not reproducible) or CloudFormation (works too, but Terraform's plan output and module ecosystem are clearer) | S3 backend, versioned + encrypted, native lockfile (`use_lockfile = true`) | GitHub Actions, all resources |
